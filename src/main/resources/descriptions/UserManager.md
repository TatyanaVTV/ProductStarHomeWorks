# Структура программы управления пользователями

Программа реализует консольное приложение для управления пользователями с использованием паттерна **Command**.


## Основные компоненты

### 1. `Action` (enum)
**Назначение:** определяет доступные действия в системе и их метаданные.

**Поля:**
- `code` — числовой идентификатор действия (например, `1` для добавления пользователя);
- `requireAdditionalData` — флаг, указывающий, требуются ли дополнительные данные для выполнения действия.

**Ключевые методы:**
- `fromCode(Integer code)` — статический метод для получения действия по его коду. Если код не найден, выводит сообщение об ошибке и возвращает `ERROR`.

---

### 2. `Command` (class)
**Назначение:** инкапсулирует команду с указанием действия (`Action`), которое нужно выполнить.

**Структура:**
- Содержит единственное поле `action` типа `Action`.

**Роль в паттерне Command:** выступает как объект запроса, передаваемый обработчику команд.

---

### 3. `InputProvider` (interface)
**Назначение:** абстрагирует источник ввода данных (позволяет легко заменять реализацию).

**Метод:**
- `getInput(String prompt)` — запрашивает у пользователя ввод с заданным приглашением.

---

### 4. `ConsoleInputProvider` (class)
**Назначение:** конкретная реализация `InputProvider` для консольного ввода.

**Реализация:**
- Использует `Scanner` для чтения данных из `System.in`.
- Выполняет `trim()` для удаления пробелов по краям перед возвратом результата.

---

### 5. `UserManagerCommand` (interface)
**Назначение:** определяет контракт для всех команд управления пользователями.

**Методы:**
- `getName()` — возвращает отображаемое имя команды (для меню);
- `execute(UserManager userManager, InputProvider inputProvider)` — выполняет логику команды.

---

### 6. Конкретные команды (реализуют `UserManagerCommand`)

#### `AddUserCommand`
**Назначение:** добавляет нового пользователя.
**Логика:**
- Запрашивает имя и город у пользователя (с проверкой формата).
- Создаёт объект `User`.
- Передаёт объект в `UserManager`.

#### `ShowAllUsersCommand`
**Назначение:** выводит список всех пользователей.
**Логика:**
- Получает список пользователей из `UserManager`.
- Если список пуст, отображает сообщение `<пусто>`.

#### `ExitCommand`
**Назначение:** завершает работу программы.

---

### 7. `UserManager` (class)
**Назначение:** центральный компонент бизнес‑логики, управляющий коллекцией пользователей.

**Функции:**
- Хранение списка пользователей.
  - При запуске приложения - загружает данные из файла, если он есть.
- Добавление новых пользователей (`addUser`).
- Предоставление доступа к списку пользователей (для отображения).

---

### 8. `UserManagerCommandHandler` (class)
**Назначение:** обработчик команд, реализующий логику паттерна Command.

**Ключевые компоненты:**
- `USER_MANAGER` — статический экземпляр `UserManager`;
- `COMMAND_MAP` — карта (`Map<Action, UserManagerCommand>`), связывающая действия (`Action`) с конкретными командами;
- `INPUT_PROVIDER` — статический экземпляр `ConsoleInputProvider`.

**Основные методы:**
- `processCommand(Command command)` — обрабатывает переданную команду: находит соответствующую реализацию в `COMMAND_MAP` и вызывает её метод `execute()`;
- `showMenu()` — отображает меню с доступными действиями (использует `COMMAND_MAP` для получения названий команд);
- `registerCommands()` — инициализирует `COMMAND_MAP`, регистрируя все доступные команды.

---

### 9. `UserManagerCheck` (class)
**Назначение:** точка входа в приложение (`main` метод).

**Логика работы:**
1. В бесконечном цикле отображает меню через `UserManagerCommandHandler.showMenu()`.
2. Считывает ввод пользователя и преобразует его в объект `Command`.
3. Передаёт команду на обработку в `UserManagerCommandHandler`.
4. При выборе действия `EXIT` завершает программу.

**Вспомогательные методы:**
- `readCommand()` — считывает ввод пользователя, преобразует его в `Action`, создаёт и возвращает объект `Command`. При ошибке возвращает команду с действием `ERROR`.

## Схема взаимодействия компонентов

1. **Пользователь** вводит номер действия в консоли.
2. **`UserManagerCheck`** считывает ввод, создаёт объект `Command` и передаёт его в `UserManagerCommandHandler`.
3. **`UserManagerCommandHandler`** находит соответствующую команду в `COMMAND_MAP` и вызывает её метод `execute()`.
4. **Конкретная команда** (`AddUserCommand`, `ShowAllUsersCommand`) выполняет свою логику, используя `UserManager` для работы с данными и `InputProvider` для взаимодействия с пользователем.
5. **Результат** отображается в консоли. Цикл повторяется до выбора действия `EXIT`.


## Ключевые преимущества архитектуры

- **Слабая связанность:** компоненты зависят от абстракций (`InputProvider`, `UserManagerCommand`), а не от конкретных реализаций.
- **Расширяемость:** добавление новой команды требует создания класса‑реализации `UserManagerCommand` и регистрации её в `COMMAND_MAP`.
- **Читаемость:** чёткое разделение ответственности между компонентами.
- **Тестируемость:** возможность подмены `InputProvider` и `UserManager` для модульного тестирования.
